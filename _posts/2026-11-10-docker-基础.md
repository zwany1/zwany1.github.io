Docker 主要依靠 Linux 内核提供的 Namespace 和 cgroups 两种机制实现容器隔离。

Namespace 主要负责资源隔离，例如隔离进程、网络、挂载点等，让不同容器拥有相对独立的资源视图。

cgroups 主要负责资源限制和统计，例如限制容器使用的 CPU、内存和磁盘 I/O，防止单个容器过度占用宿主机资源。
|对比|Docker 容器|虚拟机|
|隔离对象|进程及相关资源|虚拟硬件和完整操作系统|
|内核|共享宿主机内核|各自拥有 Guest OS 内核|
|资源开销|通常较小|通常较大|
|启动速度|通常较快|通常较慢|
|隔离边界|共享内核，需特别关注内核安全|通常有更强的系统隔离边界|

举个例子：

你有一台 Linux 服务器。

使用 Docker，可以直接运行 Java 和 MySQL 容器，不需要分别安装两套完整的 Linux 操作系统。

使用虚拟机，则可以创建两台虚拟机，每台虚拟机分别安装自己的 Linux 操作系统。

所以 Docker 更轻量的一个重要原因，就是不需要为每个容器单独运行一套操作系统内核。
Docker 容器的数据默认保存在容器的可写层中，删除容器后，可写层也会被删除，因此数据可能丢失。

为了实现数据持久化，可以使用 Docker Volume 或 Bind Mount，将容器内的数据目录挂载到容器之外的存储位置。

这样即使删除并重新创建容器，只要继续挂载原来的数据卷或宿主机目录，就可以保留之前的数据。
